Streamlit의 `st.navigation()`을 사용하면 페이지 경로를 명시적으로 지정할 수 있어.

**GitHub 저장소에서&#x20;**`code`**&#x20;폴더 안에&#x20;**`pages`**&#x20;폴더가 실제로 존재하고, 그 안에&#x20;**`1_탐색.py`**와&#x20;**`2_데이터_전처리.py`**가 있는지 확인해 줘.**

만약 폴더가 이미 정확히 존재한다면, 다음으로 GitHub 저장소의 파일 이름과 Streamlit Cloud의 실행 경로를 함께 점검해서 수정 코드를 만들어 줄게.





정확한 원인을 찾으려면 우선 `main.py`**와 두 페이지 파일의 전체 코드**를 확인하면 돼.

1. `code/main.py` 전체
2. `code/pages/1_탐색.py` 전체
3. `code/pages/2_데이터_전처리.py` 전체

**참고:** 이번 수정은 `main.py`만 변경하면 돼. 두 페이지 파일은 우선 수정하지 않아도 돼.

이렇게 수정한 뒤에도 오류가 발생한다면, 오류 메시지에 `페이지 파일을 찾을 수 없습니다`가 표시되는지 확인해 줘. 그러면 경로 문제인지 Streamlit의 페이지 등록 문제인지 구분할 수 있어.




이번에는 원인을 조금 더 정확하게 좁힐 수 있어. GitHub의 `main.py`와 오류 메시지를 대조해 보니 **중요한 불일치가 발견됐어.**

## **1. GitHub 코드와 실행 중인 코드가 서로 달라**

현재 보내 준 GitHub Raw URL의 `main.py`를 확인한 결과는 다음과 같아.

```
st.page_link(    "pages/1_탐색.py",    label="데이터 탐색",    icon="🔍")
```

그런데 Streamlit Cloud의 오류 메시지에는 다음과 같이 나와 있어.

```
st.page_link(    explore_page,    label="데이터 탐색",    icon="🔍")
```

즉, **GitHub의 현재&#x20;**`main`**&#x20;브랜치에 있는 코드와 Streamlit Cloud에서 실행되는 코드가 일치하지 않아.**&#x20;

[image](https://www.google.com/s2/favicons?domain=https://raw.githubusercontent.com\&sz=32)

GitHub



## **2. 우선 확인할 설정**

Streamlit Cloud에서 다음 항목을 확인해 줘.

| 항목             | 확인할 값                                       |
| -------------- | ------------------------------------------- |
| Repository     | `gosokturn/Analyzing-personal-Data-project` |
| Branch         | `main`                                      |
| Main file path | `code/main.py`                              |

설정이 다르다면 위 값으로 맞춰 줘.

그다음 GitHub에 최신 코드가 올라가 있는지 확인하고 Streamlit Cloud에서 앱을 재시작해 줘.

## **3. 추가로 수정할 코드**

이전 답변에서 `Path` 객체를 그대로 `st.page_link()`에 전달하도록 안내한 부분도 수정할게. `st.page_link()`에는 문자열 경로를 전달하도록 하자.

기존 사이드바 코드를 다음으로 교체해 줘.

```
# ==============================# 왼쪽 사이드바 메뉴# ==============================with st.sidebar:    st.title("📈 금융 지수 데이터 분석")    st.caption("데이터 분석 및 전처리")    st.divider()    st.subheader("📂 메뉴")    st.page_link(        "pages/1_탐색.py",        label="데이터 탐색",        icon="🔍"    )    st.page_link(        "pages/2_데이터_전처리.py",        label="데이터 전처리",        icon="🧹"    )    st.divider()    st.caption("금융 지수 데이터 분석 프로젝트")
```

## **4. 현재 가장 중요한 확인 사항**



먼저 확인

&#x20;지금은 코드를 더 복잡하게 바꾸기보다 실행 환경부터 일치시켜야 해.



GitHub의 Raw URL에 표시되는 코드와 Streamlit Cloud 오류에 표시되는 코드가 다르기 때문이야.

**Streamlit Cloud의 Settings에서 Main file path가&#x20;**`code/main.py`**로 설정되어 있는지 먼저 확인해 줘.** 이 설정이 맞는데도 같은 오류가 나면, 다음 단계로 `st.navigation()`을 이용해 페이지를 명시적으로 등록하는 방식으로 바꾸는 게 좋아.







이번에는 기존 `st.page_link()` 방식을 완전히 없애고, Streamlit에서 권장하는 `st.Page()`**와&#x20;**`st.navigation()`**&#x20;방식**으로 변경할게.

기존 GitHub의 `main.py`를 확인했어. 원본 데이터 불러오기, 행·열 개수 표시, 결측치 확인, 데이터 미리 보기 기능은 그대로 유지할게.&#x20;

[image](https://www.google.com/s2/favicons?domain=https://raw.githubusercontent.com\&sz=32)

GitHub+1



핵심은 `main.py`가 세 페이지를 직접 등록하고 관리하도록 만드는 거야. 이렇게 하면 페이지 경로를 개별 링크로 연결하다가 발생했던 오류를 피할 수 있어.

## **1.&#x20;**`code/main.py`**&#x20;전체 코드**

기존 `main.py` 내용을 전부 삭제하고 아래 코드 전체를 복사해서 붙여 넣어 줘.

```
import streamlit as stimport pandas as pdfrom pathlib import Path# ==========================================# 1. 기본 설정# ==========================================st.set_page_config(    page_title="금융 지수 데이터 분석",    page_icon="📈",    layout="wide")# ==========================================# 2. 파일 경로 설정# ==========================================BASE_DIR = Path(__file__).resolve().parentPAGES_DIR = BASE_DIR / "pages"EXPLORE_FILE = PAGES_DIR / "1_탐색.py"PREPROCESS_FILE = PAGES_DIR / "2_데이터_전처리.py"# ==========================================# 3. 페이지 파일 확인# ==========================================if not PAGES_DIR.exists():    st.error("pages 폴더를 찾을 수 없습니다.")    st.write(f"확인한 경로: {PAGES_DIR}")    st.stop()
```

## **2. 반드시 확인할 파일 구조**

## **3.&#x20;**`requirements.txt`**도 확인해 줘**

이번 코드에서 사용하는 `st.navigation()`은 Streamlit 1.36.0부터 지원돼.&#x20;
